# `infra/pages-fallback/dist` — резервная копия собранного приложения

## Что это

Готовая production-сборка Family Hub, собранная **локально** командой:

```bash
BASE_PATH=/FAMILY-HUB/ npm run build   # результат копируется в infra/pages-fallback/dist
```

Она намеренно хранится в git (обычно `dist/` в `.gitignore`, для этой папки сделано
исключение), потому что служит страховкой при публикации на GitHub Pages.

## Зачем

Workflow `deploy-preview.yml` сначала пытается собрать приложение на сервере GitHub
(как положено). Если сборка там не удалась — берётся эта копия, и владелец всё равно
получает работающую ссылку вместо красного крестика и ожидания.

Причина введения страховки: 2026-10-01 шаг сборки в CI на сервере GitHub падал
(`exit code 1`), тогда как локально тот же набор шагов — verify → lint → typecheck →
test → build — проходил чисто. Логи Actions из среды разработки не скачиваются
(хосты `*.actions.githubusercontent.com` и `*.blob.core.windows.net` недоступны),
поэтому точная причина на момент написания не установлена. Шаги сборки в CI разбиты
на `tsc -b` и `vite build` отдельно — чтобы по номеру упавшего шага понять, кто виноват.

Когда причина падения будет найдена и устранена, эту папку нужно **удалить** вместе
с fallback-веткой в workflow. Хранить собранный код в git на постоянной основе —
плохая практика: история репозитория растёт примерно на 0.5 МБ с каждой сборкой.

## Правило обновления

Обновлять копию перед каждым push, который должен попасть на Pages, если менялся код
приложения:

```bash
rm -rf dist infra/pages-fallback/dist
BASE_PATH=/FAMILY-HUB/ npm run build
mkdir -p infra/pages-fallback && cp -r dist infra/pages-fallback/dist
git add -f infra/pages-fallback/dist
```

Копия обязана быть собрана с `BASE_PATH=/FAMILY-HUB/` — иначе пути к файлам на Pages
будут неверными и страница откроется белой.
