## 0.0.1 — 2026-10-01 — ревизия решений по хостингу и уборка репозитория

Документационная версия. Код приложения по-прежнему не создавался.

### Изменено
- **Cloudflare Pages исключён из плана как запасной хостинг.** Проверка показала, что он
  ухудшил бы ситуацию: `*.pages.dev` внесён в реестр запрещённых ресурсов РФ с мая 2024
  (подтверждено измерениями RIPE Atlas по всей стране), значительная часть IP-адресов
  Cloudflare — с июня 2025, суммарный трафик из России к Cloudflare упал более чем на 50 %.
  Для использования понадобился бы платный собственный домен, что нарушает требование
  нулевой стоимости. См. `docs/RESEARCH.md` §G (факты F19–F21) и §H (таблица ответов).
- **Стратегия устойчивости заменена** на 6 пунктов в `PROJECT.md` §2.1, не зависящих от
  второго зарубежного хостинга. Введено различие двух независимых внешних каналов:
  **A — оболочка приложения** (`*.github.io`) и **B — данные семьи** (`api.github.com`).
  Cloudflare мог бы касаться только канала A и никак не касался бы канала B.
- Риск R1 в `PROJECT.md` §8 разделён на **R1a** (оболочка), **R1b** (данные) и
  **R1c** (Cloudflare недоступен — подтверждено).
- Исходные документы убраны из корня репозитория в **`docs/source/`** по просьбе владельца
  (`Promt to check.md`, `UNIVERSAL AI GUIDE (Единый мастер-промт).md`). Файлы сохранены как
  архив первоисточников, не удалены; все ссылки в документации обновлены.

### Добавлено
- `docs/RESEARCH.md`: раздел G (факты F19–F23) и раздел H (прямые ответы на вопросы
  владельца о Cloudflare), новые строки в таблице перепроверки.
- Факт **F22**: WebDAV Яндекс Диска и Облака Mail.ru бесплатен, без карты и доступен в РФ —
  кандидат на запасной канал данных, но **CORS из браузера не подтверждён** (проверить из
  среды разработки невозможно: исходящий трафик закрыт). Рабочим планом Б не объявляется.
- Факт **F23**: 14.07.2026 GitHub, Google и Apple были одновременно недоступны в России
  около часа → каналы A и B могут выпадать одновременно, offline-first обязателен.
- Пункт 4 стратегии устойчивости: **автоэкспорт данных на устройство** (локальная JSON-копия
  у семьи даже при полной недоступности GitHub).

### Честно зафиксировано
На сегодня не существует проверенной бесплатной, доступной в России и CORS-совместимой
замены GitHub для канала данных. План Б по данным не выдуман, а отложен до появления
проверенного варианта.

## 0.0.0 — 2026-10-01 — ЭТАП 0: согласование и документация

**Кода приложения нет. Это документационный этап.**

### Добавлено
- `PROJECT.md` — единый рабочий документ проекта. Объединяет исходное ТЗ
  (`Promt to check.md`), подход к взаимодействию (`UNIVERSAL AI GUIDE`), согласованные
  решения владельца, проверенные ограничения, план из 12 этапов, Definition of Done
  и форму отчёта по этапу.
- `HANDOFF.md` — точка передачи для нового диалога с любым ИИ: текущее состояние,
  принятые решения, что нельзя ломать, незакрытые вопросы Q1–Q8, действия владельца.
- `docs/RESEARCH.md` — 18 проверенных фактов (F1–F18) с источниками, датами проверки
  и уровнем уверенности. Отдельно зафиксировано, по каким вопросам данных **нет**.
- `version.json` — единственный канонический источник версии.
- `CHANGELOG.md` — этот файл.

### Решено (согласовано с владельцем)
- Хостинг: GitHub Pages; репозиторий кода — public, репозиторий семейных данных — private.
  Заложена возможность быстрого переключения на Cloudflare Pages.
- Уведомления: канальная архитектура, три уровня, переключение одним тумблером в Настройках.
  Уровень 0 (локально при открытом приложении) и Уровень 1 (ICS в нативный календарь)
  работают всегда и без внешней инфраструктуры. Уровень 2 (Web Push через GitHub Actions)
  включается только после проверки на реальных устройствах.
- Авторизация: fine-grained PAT у каждого члена семьи + локальный режим без настройки.
  GitHub App Device Flow — спайк в ЭТАПЕ 2 (CORS из браузера не подтверждён).
- Приняты 6 сокращений объёма (~минус 20% работ): вырезан Android APK; per-entity audit
  log заменён на «Семейную ленту» с сохранением полной истории только для Сроков;
  магазин стал тегом, а не сущностью; убран «приоритет» покупки; UI разрешения конфликтов
  не строится; для «Дел» и «Сроков» используется один общий движок дат и рекурренции.

### Исправлено в исходном ТЗ (найдено при анализе)
- Добавлен отсутствовавший раздел о хостинге и деплое.
- Схема «cron раз в сутки → Web Push» заменена на event-driven push-триггер
  (30–90 с вместо 15–30 мин) + ежедневный cron только для долгосрочных дат,
  с расчётом бюджета минут Actions.
- Запрещена отправка push напрямую с устройства (потребовала бы приватный VAPID-ключ
  в браузере); приватный ключ живёт только в Secrets репозитория данных.
- Закрыты 11 пробелов ТЗ: tombstones для удалений, date-only семантика дат, перекос часов
  устройства, истечение PAT через год, onboarding, модель идентичности, рост файлов,
  secondary rate limits, отсутствие install-prompt на iOS, разработка push-логики без
  доступа к семейным данным, ограничения среды разработки.

### Известные ограничения на текущий момент
- Ни одна строка кода не написана, зависимости не установлены, деплой не настроен.
- Доставка Web Push на Android в России (FCM) — **данных нет**, проверяется в ЭТАПЕ 3.
- Доступность GitHub из России деградирует (10–16% неудачных подключений с мая 2026) —
  смягчается offline-first и Plan B по хостингу.
