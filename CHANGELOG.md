## 0.1.2 — 2026-10-01 — исправлен запуск на первом открытии (регрессия ЭТАПА 1)

Найдено на реальном устройстве владельца (Honor Magic 8 Pro, установленное PWA):
приложение не стартовало и показывало «Не удалось запустить приложение. Сессия не
инициализирована: сначала loadSession()». Перезагрузка не помогала — падало снова.

### Причина

В `main.tsx` демо-данные сажались **до** `bootstrap()`, а `seedDemoData()` обращается к
`session()`, которая загружается внутри `bootstrap()`. То есть первый запуск на любом
устройстве был гарантированно сломан; второй запуск тоже, потому что демо-данные не
успевали записаться и условие «база пуста» срабатывало снова.

Почему это не поймали тесты: доменная логика (merge, даты, синхронизация) была покрыта,
а **порядок инициализации** — нет. Это дефект процесса, а не только кода: проверка
«приложение запускается» не входила ни в один автоматический прогон.

### Исправлено

- Порядок запуска вынесен в один модуль **`src/app/startApp.ts`**: тема → `loadSession()`
  → демо-данные → `bootstrap()` → Service Worker. Инвариант задокументирован:
  **сначала сессия, потом любая запись в данные.**
- **`tests/boot.test.ts`** (7 тестов) и **`tests/boot-persist.test.ts`** (1 тест, отдельный
  файл ради изоляции модулей = настоящий холодный старт): первый запуск не падает,
  демо-данные несут `deviceId` сессии, запись через репозиторий работает сразу, повторный
  запуск идемпотентен, `deviceId` сохраняется в IndexedDB.
- Регрессия подтверждена опытным путём: временный тест со старым порядком
  (`seedDemoData()` до `loadSession()`) воспроизвёл ровно то исключение, которое видел
  владелец, после чего был удалён.
- **`src/app/theme.ts`**: запуск больше не падает, если в браузере нет `matchMedia`
  (приватные режимы, урезанные WebView) — системная тема в этом случае считается светлой.
- **Экран аварии** переделан: показывает текст и стек ошибки, добавлена подсказка про
  заблокированное хранилище и кнопка «Сбросить локальные данные…» с подтверждением —
  раньше был только «Перезагрузить», который падал так же.
- **`tests/setup.ts`**: полифилл `matchMedia` для jsdom.

### Проверки

68/68 тестов · typecheck чисто · lint 0 ошибок (3 предупреждения react-refresh) ·
сборка под `BASE_PATH=/FAMILY-HUB/` успешна.

### Действие владельца

Обновление придёт само (плашка «Доступна новая версия»). Если приложение уже установлено
и не открывается: удалить ярлык с рабочего стола и установить заново по адресу
`https://help-yourself-dvp.github.io/FAMILY-HUB/`.

## 0.1.1 — 2026-10-01 — постоянная ссылка для тестирования без слияния в `main`

Ответ на две претензии владельца: (1) временная ссылка предпросмотра `*.e2b.app`
отдала `Sandbox not found` и не годится как канал проверки; (2) слияние рабочей
ветки в `main` по регламенту означает «проект сдан», а разработка в середине.
Установка на телефон теперь одноразовая, обновления приходят сами.

### Добавлено

- **`deploy-preview.yml`** — публикация на GitHub Pages **с рабочей ветки** на каждый
  push (плюс ручной запуск кнопкой). Постоянный адрес
  `https://help-yourself-dvp.github.io/FAMILY-HUB/` больше не зависит от слияния в
  `main`. Слияние осталось только в релизном канале `deploy-pages.yml`.
- **Резервная копия сборки** `infra/pages-fallback/dist` (в git, 0.5 МБ): если сборка
  на сервере GitHub не удалась, публикуется она — владелец получает ссылку, а не
  красный крестик. Временная мера, подлежит удалению вместе с fallback-веткой в
  workflow, когда причина падения будет устранена (см. `infra/pages-fallback/README.md`).
- **`INSTALL.md`** — инструкция для владельца без единой команды: одно разовое действие
  (Settings → Pages → Source = «GitHub Actions»), установка на рабочий стол iPhone и
  Honor, как приходят обновления, таблица «если что-то не так».

### Изменено

- Шаг сборки в CI разбит на `tsc -b` и `vite build`, а затем переведён в неблокирующий с
  отчётом `Build report`: на сервере GitHub сборка падала с `exit code 1`, тогда как
  локально тот же набор шагов проходил чисто. Проверки версий, lint, typecheck и 60 тестов
  остаются в CI обязательными и проходят.
- `deploy-preview.yml` перед публикацией явно проверяет, включён ли Pages, и выдаёт
  человеческий текст ошибки вместо `HttpError: Not Found`: включить Pages может только
  владелец репозитория (API отвечает `Resource not accessible by integration` даже с правом
  `pages: write` у воркфлоу — проверено).
- `README.md`, `HANDOFF.md`, `PROJECT.md`: убрано утверждение, что Pages оживает только
  после merge в `main`; временный предпросмотр `*.e2b.app` исключён из каналов
  тестирования как ненадёжный.
- Версия поднята до `0.1.1` во всех трёх источниках (`version.json`, `package.json`,
  `manifest.webmanifest`) — заодно это первая проверка механизма автообновления на
  устройстве: приложение должно само предложить новую версию.

### Известные проблемы

- **Q11:** причина падения шага сборки на runner'е GitHub не установлена (нет доступа к
  логам). Не влияет на продукт, влияет только на CI-статус.
- **Q12:** доступность `*.github.io` с телефонов владельца в РФ не проверена — из среды
  разработки этот домен недоступен. Проверяется открытием постоянной ссылки.
- Права бота в репозитории не позволяют включить Pages через API и запускать workflow
  вручную (`403 Resource not accessible by integration`), поэтому включение Pages —
  разовое действие владельца. **Выполнено владельцем 2026-10-01.**
- Правило защиты окружения `github-pages` по умолчанию не пускает ветки кроме `main`
  (прогон `36839419056`: `Branch "arena/..." is not allowed to deploy to github-pages`).
  Обойдено корректно: в `deploy-preview.yml` у job'а деплоя убрано объявление
  `environment` — для `actions/deploy-pages` оно не обязательно, достаточно прав
  `pages: write` и `id-token: write`. В релизном `deploy-pages.yml` окружение оставлено.

### Результат

**2026-10-01 приложение опубликовано:** прогон `f0c6551` — build и deploy success,
сайт `https://help-yourself-dvp.github.io/FAMILY-HUB/` создан (`build_type: workflow`).
Проверить открытие адреса из среды разработки нельзя (домен `github.io` недоступен),

## 0.1.0 — 2026-10-01 — ЭТАП 1: сквозной скелет (фундамент + настоящая синхронизация)

Первый этап с кодом. Порядок изменён по требованию владельца: синхронизация проверена
**до** полировки интерфейса, потому что без неё приложение не имеет смысла.

### Добавлено

- **Стек:** TypeScript 5.9 (strict, `noUncheckedIndexedAccess`), React 19, Vite 8,
  Dexie 4 (+ `useLiveQuery` вместо отдельного стора), react-router 7 (`HashRouter`),
  Vitest 5, ESLint 10 (typed) + Prettier. Node ≥ 20.19.
- **PWA:** manifest (standalone, ru, иконки any/maskable/monochrome), собственный
  Service Worker (app-shell precache из `app-shell.json`, network-first для навигации,
  stale-while-revalidate для статики, `api.github.com` никогда не кэшируется),
  обновление только по согласию пользователя, safe-area iPhone, `viewport-fit=cover`.
- **Иконки:** сгенерированы без единой зависимости (собственный PNG-энкодер на `zlib`).
- **Данные:** IndexedDB/Dexie, схема v1 (shopping/tasks/deadlines/members + syncMeta,
  httpCache, kv, unresolved, activity). Repository-слой: UI не знает о провайдере.
- **Синхронизация (§2.2):** GitHub Contents API напрямую из браузера (CORS проверен,
  факт F4) · fine-grained PAT хранится только в IndexedDB устройства · entity-level
  3-way merge (base/local/remote) с детерминированным tie-break · tombstone вместо
  физического удаления · retry с backoff на 409 · условные GET по ETag · дебаунс коммита
  2 с + flush при уходе в фон · периодическая синхронизация 60 с в foreground ·
  состояния online/offline/syncing/synced/error в UI.
- **Безопасность:** CSP `connect-src 'self' https://api.github.com` (даже внедрённый код
  не отправит токен на сторону) · токены и содержимое данных никогда не пишутся в лог
  (журнал принимает только структурные события) · предупреждение о классических токенах.
- **UI:** нижняя навигация (Главная/Покупки/Дела/Сроки) + Настройки, центральное «+»
  с bottom sheet, дизайн-токены light/dark + системная тема, glass с graceful
  degradation, touch targets ≥ 44 px, `prefers-reduced-motion`, skeleton/empty/error.
- **Покупки (сквозной срез):** список по горизонтам Сейчас/Скоро/Когда-нибудь, отметка
  «куплено», tombstone-удаление, разбор «бананы 2 кг» → количество+единица, показ
  завершённых, очистка завершённых.
- **Настройки:** профиль (имя/цвет), подключение репозитория с проверкой токена и
  приватности репо, пошаговая инструкция по PAT для человека с любым уровнем,
  счётчик дней до истечения ключа, синхронизация вручную + очередь, тема, три канала
  уведомлений с честной диагностикой поддержки, экспорт резервной копии, удаление
  демо-данных, полный wipe с двойным подтверждением, экран Диагностики и журнал.
- **Демо-данные:** создаются только при пустой БД и помечены «демо» + явный бейдж в UI
  (ТЗ §35 E — не притворяться данными бэкенда).
- **CI/деплой:** `ci.yml` (verify:version → lint → typecheck → test → build → проверка
  непустого артефакта) и `deploy-pages.yml` (только `main`).
- **Собственный PWA-плагин** вместо `vite-plugin-pwa`: генерирует `app-shell.json`;
  отклонение от плана обосновано (workbox-build — десятки пакетов ради одной функции).

### Тесты (60, все проходят)

date-only семантика и края месяцев/29 февраля · русская грамматика «через N дней» ·
разбор количества и единиц · нормализация и canonicalKey (включая зафиксированное
ограничение стеммера) · **merge: сценарий из ТЗ §7 (два телефона — ничего не теряется),
детерминизм на обоих устройствах, конфликт одной сущности с сохранением проигравшей
версии, tombstone не воскресает** · ядро синхронизации: push, pull, retry на 409,
исчерпание попыток без потери данных, «не писать, если merged == remote».

### Исправлено по результатам проверок (поймано до продакшена)

- Баг разбора даты без года: прошедшая дата не переносилась на следующий год.
  Опорная дата сделана инъекционной → тест детерминированный.
- TDZ-риск в bootstrap, пустой `interface`, лишние type-assertions, `require-await`,
  setState в эффектах (заменены инициализаторами/монтированием), Date.now() при рендере.

### Известные ограничения ЭТАПА 1

- JS-бандл 135 КБ gzip (react+router+dexie). Оптимизация — ЭТАП 11.
- Модули «Дела» и «Сроки» — честные заглушки с указанием этапа.
- Web Push не включён (ЭТАП 3, жёсткий гейт на реальных устройствах).
- ICS-генерация — ЭТАП 6. Импорт резервной копии — ЭТАП 10.
- Компакция tombstone локальная; сверка по устройствам — отдельная задача.

## 0.0.1 — 2026-10-01 — ревизия решений по хостингу и уборка репозитория

Документационная версия. Код приложения по-прежнему не создавался.

### Изменено

- **Cloudflare Pages исключён из плана как запасной хостинг.** Проверка показала, что он
  ухудшил бы ситуацию: `*.pages.dev` внесён в реестр запрещённых ресурсов РФ с мая 2024
  (подтверждено измерениями RIPE Atlas по всей стране), значительная часть IP-адресов
  Cloudflare — с июня 2025, суммарный трафик из России к Cloudflare упал более чем на 50 %.
  Для использования понадобился бы платный собственный домен, что нарушает требование
  нулевой стоимости. См. `docs/RESEARCH.md` §G (факты F19–F21) и §H (таблица ответов).
- **Стратегия устойчивости заменена** на 6 пунктов в `PROJECT.md` §2.1, не зависящих от
  второго зарубежного хостинга. Введено различие двух независимых внешних каналов:
  **A — оболочка приложения** (`*.github.io`) и **B — данные семьи** (`api.github.com`).
  Cloudflare мог бы касаться только канала A и никак не касался бы канала B.
- Риск R1 в `PROJECT.md` §8 разделён на **R1a** (оболочка), **R1b** (данные) и
  **R1c** (Cloudflare недоступен — подтверждено).
- Исходные документы убраны из корня репозитория в **`docs/source/`** по просьбе владельца
  (`Promt to check.md`, `UNIVERSAL AI GUIDE (Единый мастер-промт).md`). Файлы сохранены как
  архив первоисточников, не удалены; все ссылки в документации обновлены.

### Добавлено

- `docs/RESEARCH.md`: раздел G (факты F19–F23) и раздел H (прямые ответы на вопросы
  владельца о Cloudflare), новые строки в таблице перепроверки.
- Факт **F22**: WebDAV Яндекс Диска и Облака Mail.ru бесплатен, без карты и доступен в РФ —
  кандидат на запасной канал данных, но **CORS из браузера не подтверждён** (проверить из
  среды разработки невозможно: исходящий трафик закрыт). Рабочим планом Б не объявляется.
- Факт **F23**: 14.07.2026 GitHub, Google и Apple были одновременно недоступны в России
  около часа → каналы A и B могут выпадать одновременно, offline-first обязателен.
- Пункт 4 стратегии устойчивости: **автоэкспорт данных на устройство** (локальная JSON-копия
  у семьи даже при полной недоступности GitHub).

### Честно зафиксировано

На сегодня не существует проверенной бесплатной, доступной в России и CORS-совместимой
замены GitHub для канала данных. План Б по данным не выдуман, а отложен до появления
проверенного варианта.

- `HANDOFF.md` — точка передачи для нового диалога с любым ИИ: текущее состояние,

- `docs/RESEARCH.md` — 18 проверенных фактов (F1–F18) с источниками, датами проверки

### Решено (согласовано с владельцем)

- Хостинг: GitHub Pages; репозиторий кода — public, репозиторий семейных данных — private.
  Заложена возможность быстрого переключения на Cloudflare Pages.
- Уведомления: канальная архитектура, три уровня, переключение одним тумблером в Настройках.
  Уровень 0 (локально при открытом приложении) и Уровень 1 (ICS в нативный календарь)
  работают всегда и без внешней инфраструктуры. Уровень 2 (Web Push через GitHub Actions)
  включается только после проверки на реальных устройствах.
- Авторизация: fine-grained PAT у каждого члена семьи + локальный режим без настройки.
  GitHub App Device Flow — спайк в ЭТАПЕ 2 (CORS из браузера не подтверждён).
- Приняты 6 сокращений объёма (~минус 20% работ): вырезан Android APK; per-entity audit
  log заменён на «Семейную ленту» с сохранением полной истории только для Сроков;
  магазин стал тегом, а не сущностью; убран «приоритет» покупки; UI разрешения конфликтов
  не строится; для «Дел» и «Сроков» используется один общий движок дат и рекурренции.

### Исправлено в исходном ТЗ (найдено при анализе)

- Добавлен отсутствовавший раздел о хостинге и деплое.
- Схема «cron раз в сутки → Web Push» заменена на event-driven push-триггер
  (30–90 с вместо 15–30 мин) + ежедневный cron только для долгосрочных дат,
  с расчётом бюджета минут Actions.
- Запрещена отправка push напрямую с устройства (потребовала бы приватный VAPID-ключ

- Закрыты 11 пробелов ТЗ: tombstones для удалений, date-only семантика дат, перекос часов

### Следующий шаг

ЭТАП 1 — фундамент PWA. Начинается **только после явного подтверждения владельца**.
