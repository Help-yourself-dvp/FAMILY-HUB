# FAMILY HUB

Приватное offline-first PWA для одной семьи из 2–4 человек: **Главная · Покупки · Дела ·
Сроки · Настройки**. Нулевая стоимость разработки и использования, никаких AI API,
никаких сторонних сервисов в рантайме.

Целевые устройства: iPhone 16 (Safari → «На экран Домой») и Honor Magic 8 Pro (Android).

Диалог может потеряться в любой момент, поэтому проект не держит информацию только
в переписке. Чтобы продолжить **с последней точки, а не с начала**:

2. Прочитайте [`PROJECT.md`](PROJECT.md) — согласованная архитектура и правила работы.
3. Прочитайте [`docs/RESEARCH.md`](docs/RESEARCH.md) — факты, чтобы не исследовать заново.
4. Соблюдайте [`PROJECT.md`](PROJECT.md) §7 (протокол этапов) и §9.3 (ограничения среды).

**Не пересматривайте согласованные решения молча** и **не переходите к следующему этапу
без подтверждения владельца**.

## 🏗 Кратко об архитектуре

```
PWA (React + TypeScript + Vite)
  ↓  offline-first
IndexedDB (Dexie)  ── очередь изменений, кэш, локальные настройки
  ↓  repository layer (UI не знает о провайдере)
GitHub Contents API  ── приватный репозиторий family-hub-data, источник истины
  ↓  push event на каждый commit
GitHub Actions  ── Web Push (VAPID в Secrets) + ежедневный cron для долгосрочных дат
```

Ключевые свойства:

- **IndexedDB — кэш, GitHub — источник истины.** Потеря локальных данных на устройстве
  восстанавливается одной загрузкой.
- **Ноль секретов в коде.** Fine-grained PAT вводит пользователь; он хранится только
  в IndexedDB его устройства. CSP `connect-src` ограничен `api.github.com` — даже
  внедрённый чужой код не сможет отправить токен на сторонний домен.
- **Конфликты двух телефонов решаются entity-level merge**, а не перезаписью файла:
  добавленное на одном устройстве не теряет добавленное на другом.
- **Уведомления — три независимых канала**, переключаемые одним тумблером. Два из них
  не требуют никакой внешней инфраструктуры и работают при недоступности GitHub
  и push-сервисов.
- **Два независимых внешних канала** — оболочка приложения (`*.github.io`) и данные
  (`api.github.com`). Установленная PWA работает из кэша Service Worker даже при
  недоступности обоих; данные дополнительно копируются экспортом на устройство.

## 💰 Стоимость

**0 рублей.** GitHub Free (Pages + Actions), никаких платных API, никаких подписок,
никаких AI API, никаких сторонних сервисов в рантайме.

Единственный известный лимит, за которым надо следить: **2000 минут GitHub Actions
в месяц** на приватном репозитории данных. Расчётный расход — 1250–1850 мин/мес.
Контроль — в Настройках → Диагностика.

## 🚀 Запуск и проверки

```bash
npm ci             # установка зависимостей (lock-файл зафиксирован)
npm run dev        # разработка
npm run build      # production-сборка в dist/ (BASE_PATH из env, по умолчанию '/')
npm run preview    # предпросмотр production-сборки на 0.0.0.0:4173
npm run verify:version  # сверка версий: version.json — единственный источник
npm run lint       # ESLint (typed)
npx tsc -b         # typecheck (strict)
npm run test       # Vitest (60 тестов критичной логики)
npm run check      # lint + test + build одной командой
```

### Как проверить синхронизацию на двух телефонах

1. Создайте приватный репозиторий `family-hub-data` и fine-grained PAT
   (подробная инструкция — в приложении: Настройки → «Инструкция»).
2. Откройте приложение на **обоих** телефонах, в Настройках укажите владельца,
   репозиторий, ветку и ключ → «Проверить и подключить».
3. Добавьте покупку на одном телефоне → через ~2 секунды (дебаунс) она уйдёт в
   репозиторий и появится на втором при следующей синхронизации (до 60 с в фоне,
   мгновенно при открытии приложения).
4. Проверьте офлайн: включите авиарежим, добавьте покупку, выключите авиарежим —
   позиция не должна потеряться.

### Структура проверок

Критичная логика (merge, tombstone, даты, разбор ввода, retry на 409) покрыта
юнит-тестами; CI прогоняет lint → typecheck → test → build → проверку непустого
артефакта на каждый push.
