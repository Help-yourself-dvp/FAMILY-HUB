# FAMILY HUB

Приватное offline-first PWA для одной семьи из 2–4 человек: **Главная · Покупки · Дела ·
Сроки · Настройки**. Нулевая стоимость разработки и использования, никаких AI API,
никаких сторонних сервисов в рантайме.

Целевые устройства: iPhone 16 (Safari → «На экран Домой») и Honor Magic 8 Pro (Android).

Web Push при закрытом приложении (ручная проверка Honor подтверждена, iPhone/cron ещё на приёмке). В 0.3.6
переключатели восстанавливают состояние: push по подписке браузера, календарь
по факту скачивания файла. В 0.3.7 нажатие на уведомление открывает раздел
источника, диагностика различает настоящий push и показ при открытии; календарь
экспортирует обычные события 09:00 (Москва) и даёт проверочный файл. Прямой
импорт одного проверочного события в Honor подтверждён владельцем, полный файл
и будильник ещё на приёмке; Google официальный путь — веб-импорт с компьютера
(RESEARCH F24). В 0.3.8 круглый + открывает форму срока, а ручной workflow
отправляет независимую проверку push без создания срока. 248 тестов, typecheck, lint без ошибок и сборка;
публикация — GitHub Pages из рабочей ветки. Исправления sender пока только
в ветке сессии: для ручного теста выбрать её в Run workflow; cron берёт main.

Актуальное состояние и порядок продолжения работы — всегда в
[`HANDOFF.md`](HANDOFF.md) (переписан 2026-10-02 под «холодный старт» нового

## 🏗 Кратко об архитектуре

```
PWA (React + TypeScript + Vite)
  ↓  offline-first
IndexedDB (Dexie)  ── очередь изменений, кэш, локальные настройки
  ↓  repository layer (UI не знает о провайдере)
GitHub Contents API  ── приватный репозиторий family-hub-data, источник истины
  ↑  читает отдельный отправитель (семейный ключ в Secrets, не в коде)
GitHub Actions в ПУБЛИЧНОМ FAMILY-HUB ── Web Push, cron */30 + ручной запуск
```

Ключевые свойства:

- **IndexedDB — кэш, GitHub — источник истины.** Потеря локальных данных на устройстве
  восстанавливается одной загрузкой.
- **Ноль секретов в коде.** Fine-grained PAT вводит пользователь; он хранится только
  в IndexedDB его устройства. CSP `connect-src` ограничен `api.github.com` — даже
  внедрённый чужой код не сможет отправить токен на сторонний домен.
- **Конфликты двух телефонов решаются entity-level merge**, а не перезаписью файла:
  добавленное на одном устройстве не теряет добавленное на другом.
- **Уведомления — три независимых канала**, переключаемые одним тумблером. Два из них
  не требуют никакой внешней инфраструктуры и работают при недоступности GitHub
  и push-сервисов.
- **Два независимых внешних канала** — оболочка приложения (`*.github.io`) и данные
  (`api.github.com`). Установленная PWA работает из кэша Service Worker даже при
  недоступности обоих; данные дополнительно копируются экспортом на устройство.

## 💰 Стоимость

**0 рублей.** GitHub Free (Pages + Actions), никаких платных API, никаких подписок,
никаких AI API, никаких сторонних сервисов в рантайме.

Отправитель живёт только в публичном FAMILY-HUB (минуты GitHub-hosted runners
бесплатны без лимита). В приватном family-hub-data workflows не запускаются:
его 2000 минут/месяц не расходуются.

## 🚀 Запуск и проверки

```bash
npm ci             # установка зависимостей (lock-файл зафиксирован)
npm run dev        # разработка
npm run build      # production-сборка в dist/ (BASE_PATH из env, по умолчанию '/')
npm run preview    # предпросмотр production-сборки на 0.0.0.0:4173
npm run verify:version  # сверка версий: version.json — единственный источник
npm run lint       # ESLint (typed)
./node_modules/.bin/tsc -b  # typecheck (strict, локальный TypeScript 5.x)
npm run test       # Vitest (245 тестов)
npm run check      # lint + test + build одной командой
node scripts/make-icons-from-png.mjs <ваш-квадрат.png>  # иконки из картинки владельца
node scripts/make-icons-from-png.mjs <png> --check      # только проверить исходник
```

### Как проверить синхронизацию на двух телефонах

1. Создайте приватный репозиторий `family-hub-data` и fine-grained PAT
   (подробная инструкция — в приложении: Настройки → «Инструкция»).
2. Откройте приложение на **обоих** телефонах, в Настройках укажите владельца,
   репозиторий, ветку и ключ → «Проверить и подключить».
3. Добавьте покупку на одном телефоне → через ~2 секунды (дебаунс) она уйдёт в
   репозиторий и появится на втором при следующей синхронизации (до 60 с в фоне,
   мгновенно при открытии приложения).
4. Проверьте офлайн: включите авиарежим, добавьте покупку, выключите авиарежим —
   позиция не должна потеряться.

### Структура проверок

Критичная логика (merge, tombstone, даты, разбор ввода, retry на 409) покрыта
юнит-тестами; CI прогоняет lint → typecheck → test → build → проверку непустого
артефакта на каждый push.


### Проверка закрытого push (0.3.8)

Новый срок для этого теста **не нужен**. Закройте PWA/заблокируйте телефон,

не меняет сроки/маркеры. Успех провайдера не равен получению на телефоне;

### Дела: уведомления и Главная (0.4.1)

- На Главной появился раздел «Ближайшие дела»: открытые дела с датой, до трёх,
  с исполнителем и ссылкой в раздел «Дела».
- Уведомления дел приходят **только исполнителю**: одно, когда дело назначил
  другой участник, и одно в день срока — в том числе если назначили себе.
  Дело без исполнителя уведомлений не даёт. Каждое событие отправляется один раз.
- Уведомления работают локально, фоновой проверкой Android и (после переноса
  исправлений в main) серверным отправителем. iPhone фоновой проверки не имеет.
- В Настройках → Уведомления есть «Проверить будильник через 5 минут»: скачивается
  отдельное вымышленное событие с напоминанием за минуту до начала. Если телефон
  не показывает будильник даже для него — дело в разрешениях/батарее/«Не беспокоить»
  календаря, а не в файле.

### Что показала диагностика 03.10

Утреннее напоминание о вчерашнем тестовом сроке пришло от **фоновой проверки
телефона** (10:38 по Москве), а не от отправителя GitHub: серверных push сегодня
не было. Фоновая проверка выбирает время сама (Chrome), поэтому 09:00 не гарантировано.
Для iPhone нужен именно серверный push — он требует переноса исправлений в main,
который пока не разрешён. Автоматическое расписание main по-прежнему не исправлено.


### Календарь без дублей и включение push (0.4.2)

- У каждого срока в списке есть кнопка с календарём: скачивается файл **ровно с одним
  событием**. Это ответ на то, что телефон при импорте берёт из файла все события разом.
- Общая кнопка выгружает только то, чего не было в прежних выгрузках («только новое»);
  полная выгрузка и сброс отметок — в Настройках → Уведомления.
- Сайт не имеет доступа к системному календарю телефона: событие всегда подтверждает
  человек. «Открыть в Google Календаре» — быстрая подстановка события без наших
  будильников (их задаёт сам календарь).
- Включение push больше не пугает «сервисами Google» при сбое записи в семейное
  хранилище: конфликт одновременной записи автоматически повторяется, а сообщения
  объясняют реальную причину. Подписка хранится в телефоне, повтор остаётся безопасным.


### Календарь: одна галочка (0.4.3)

- В форме срока есть галочка **«Добавить в календарь телефона»**. При сохранении
  открывается окно создания записи с названием, датой и временем — вы нажимаете
  «Сохранить» сами. Выбор галочки запоминается.
- Запасной путь — кнопка «Выгрузить все сроки файлом (.ics)» в разделе Сроки: в файле
  сразу все события, телефон добавит их все.
- Честно: сайт не открывает системный календарь Honor — окно создания даёт Google
  Календарь (приложение или веб-форма). Напоминания там обычные, из настроек календаря;
  ступени «за 30/7/0 дней» ведёт само приложение. Если нужен календарный будильник за
  несколько дней — используйте файл .ics: он несёт наши напоминания.


### Исправление: «Ошибка: network / Failed to fetch» (0.4.4)

В версиях 0.4.2–0.4.3 синхронизация не работала: приложение отправляло заголовок,
который GitHub не разрешает в предварительном CORS-запросе, и браузер отклонял все
обращения к хранилищу, хотя интернет был в порядке. Заголовок убран, свежесть чтения
запрашивается иначе, а тест теперь не даёт добавить «свой» заголовок снова. Данные
при этом никуда не пропадали — они хранятся в телефоне и отправятся в семейное
хранилище после обновления.


### Календарь: что важно знать (0.4.5)

- При сохранении срока с галочкой приложение пытается открыть **календарь телефона**
  (`intent:`), а если не получится — веб-форму Google Календаря.
- Веб-форма сохраняет событие **в аккаунт, под которым вы вошли в браузере**. Если это
  не тот аккаунт, что включён в календаре телефона, записи там не будет.
- Надёжнее и удобнее кнопка **«Файлом в календарь телефона»**: файл открывается
  приложением календаря телефона — крупное окно, событие попадает в ваш календарь и
  сохраняет напоминания приложения.
- Открыть окно создания события прямо в приложении календаря с сайта нельзя — так
  устроен Android.
