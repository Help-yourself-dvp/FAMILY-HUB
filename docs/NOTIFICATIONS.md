# Уведомления: политика и экономика (анализ 2026-10-01, вопрос владельца приёмки 0.1.9)

Цель владельца: «не дёргать телефон лишним разом и не тратить бесплатные минуты
GitHub, которые рассчитаны впритык». Ниже — матрица событий и расчёт стоимости
каждого канала. Решения без слова владельца не реализуются (PROJECT.md §7).

## Матрица событий

| Событие                                                          | Где видно                        | Уведомление                                 | Почему                                 |
| ---------------------------------------------------------------- | -------------------------------- | ------------------------------------------- | -------------------------------------- |
| Семья добавила/купила/удалила, приложение ОТКРЫТО                | маркер статуса + семейная лента  | нет                                         | человек и так смотрит в экран          |
| То же, приложение ЗАКРЫТО                                        | лента после входа                | push уровня 1, **дайджестом**               | полезно, но не по писку на позицию     |
| Ошибка, требующая действия (ключ истёк, нет доступа к хранилищу) | плашка в приложении              | push уровня 0                               | молча данные не уедут — нужно действие |
| Приложение обновилось                                            | плашка «обновилось с версии X»   | нет                                         | обновление не требует решения          |
| Напоминание о сроке (ЭТАП 6)                                     | лента + маркер                   | push уровня 1, один раз в назначенное время | суть напоминаний                       |
| Смена профиля, технические события синхронизации                 | только диагностика               | никогда                                     | служба, не семья                       |
| Конфликт слияния, разрешённый автоматически                      | лента («требует внимания» позже) | нет, пока нет ручного разрешения            | ЭТАП 11                                |

Дайджест вместо писка: не более одного push на устройство в 30–60 минут,
текстом «Семья: 3 изменения в списке», без перечисления покупок (приватность и
спокойствие).

## Экономика минут GitHub Actions

- Приватный репозиторий (`family-hub-data`) на бесплатном тарифе ест общие
  2000 минут/месяц организации. Любой workflow в нём — расход.
- Публичный репозиторий (`FAMILY-HUB`) минуты не лимитирует вовсе.
- Вывод: отправитель push живёт ТОЛЬКО в публичном репозитории и читает данные
  через секретный ключ с правом чтения одного приватного репозитория. Платные
  минуты не расходуются независимо от частоты.
- Частота: cron раз в 30 минут = ~1440 запусков/месяц по 20–30 с ≈ 10–12 часов
  рантайма — всё в публичном репозитории, т.е. 0 платных минут. Дайджест
  означает, что устройствa получают ≤ 1 push за интервал, а не за каждое изменение.
- Устройство-инициатор (workflow_dispatch на каждое изменение) отвергнуто: шум и
  зависимость от того, открыто ли приложение у отправителя.
- Совсем без push (только локальные уведомления при открытом приложении) = 0
  минут и 0 новых механизмов: это вариант «минимум» на ближайшие этапы.

## РЕШЕНИЕ ВЛАДЕЛЬЦА (2026-10-01, приёмка 0.1.10) — действует вместо рекомендации

1. **Уведомления нужны в первую очередь для долгосрочных напоминаний**: истечение
   сроков документов, мероприятия и прочее (модуль «Сроки», ЭТАП 6).
2. **Push о покупках — отдельный переключатель в настройках, выключен по
   умолчанию**, мера «на всякий случай»: при наполнении корзины пуши были бы
   спамом. Реализован переключатель `notify.shoppingPush` (0.1.11); доставка
   включится на ЭТАПЕ 3 и только дайджестом (≤ 1 push / 30 минут).
3. **Уведомлять о действительно важных событиях, включая работоспособность
   приложения**: ключ истёк/отозван, нет доступа к хранилищу, репозиторий не
   найден, данные повреждены (healthWatch, 0.1.11, уровень 0 локально; push тем
   же правилом на ЭТАПЕ 3). **Потерю сети и таймауты НЕ уведомляем** — преходящее.
4. Push «на каждое событие» не делать никогда: шум, батарея, минус доверие.
5. Экономика минут не меняется: любой отправитель push живёт только в ПУБЛИЧном
   репозитории FAMILY-HUB (0 платных минут приватного family-hub-data).

## iOS-особенности (RESEARCH.md F7–F8)

Web Push в PWA — с iOS 16.4 и только после явного «Разрешить» в установленном
приложении; silent push запрещён (каждое сообщение видимое). Digest-модель
совместима с этим ограничением естественно.

## СТАТУС РЕАЛИЗАЦИИ (обновлено 2026-10-02, версия 0.3.7)

- Уровень 0 (локально при открытом приложении) — работает: напоминания о сроках
  (ступень в день, просрочка один раз) и «здоровье» приложения.
- Уровень 1 (ICS) — экспорт есть, живой импорт владельцем не подтверждён:
  ни Google, ни Honor не показали записи. 0.3.7, формат 2: обычные события
  09:00–09:15 (Москва), полный timezone, DTEND, UTF-8 folding и точные ступени.
  Число/даты видны после экспорта; пустой файл не считается успехом. Проверочный
  календарь — только вымышленное событие завтра, не семейный резерв.
  Google официальный импорт — веб-версия на компьютере; простое открытие файла
  на Android не гарантирует добавления (F24). Honor прямой импорт неизвестен.
  Флаг `notify.channels.ics` — только скачивание; удалить импортированные события
  или подтвердить импорт браузер не может.
- Уровень 2 (Web Push) — подписка есть, доставка при блокировке пока не подтверждена.
  Владелец пробовал новый срок: пришло при открытии. API 02.10 11:00 UTC:
  active, один manual run `36990500361` (main/e7a39b8, success), schedule 0 за >2 ч.
  Main всё ещё старый: нет npm ci и неверный формат сроков; результат success
  не подтверждает отправку. Actions permissions недоступны боту (403), точную
  причину schedule=0 не установили. Владелец выбрал без main/PR; ручная приёмка
  возможна с выбором `arena/01a0fbcb-family-hub`. В ветке sender исправлен,
  priority high, публичный HTTPS-контакт VAPID, ошибки зависимости/401/403 дают
  error annotation и exit 1, cron подготовлен 17/47 (не поменял main).
- 0.3.7: обработчик push записывает только received/shown и времена; foreground
  и PBS имеют отдельные счётчики. Это не тексты/ID/токены/подписки. При копировании
  диагностического отчёта они перечитываются, протокол активного SW должен быть `2`.
  Принятие showNotification системой не доказывает видимость на заблокированном
  экране. Нажатие открывает раздел источника; чужой URL/чужое PWA не используются.
  После уже обработанного push/PBS локальный запуск не показывает дубль; после
  сбоя локального показа маркер не ставится и попытка не теряется.
- Android PBS — дополнительный резерв, Chrome выбирает момент; 12 часов не
  гарантированы, фактический интервал Honor не измерен. iPhone PBS не имеет.
- Push покупок (дайджест ≤1/30 мин) — переключатель в настройках есть
  (`notify.shoppingPush`, выкл по умолчанию), доставка не реализована: по
  политике владельца это мера «на всякий случай», приоритет у напоминаний.
